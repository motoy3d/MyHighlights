# #123 アプリのアイコンに「まだ見ていないお知らせ」の数を出す 設計

関連：#110（Web プッシュ通知）、設計書 `docs/design/110-web-push.md`

## 1. 目的

ホーム画面に追加したアプリのアイコンに、**まだ見ていないお知らせの数**を出す。
アプリを開かなくても「何か届いている」と気づけるようにする。アプリを開けば消える。

## 2. 何を数えるか（2026-09-24 決定）

**送ったプッシュ通知のうち、まだアプリを開いて見ていないものの数。**
新しい投稿・コメント・予定の変更など、通知の種類を区別せず 1 件ずつ数える。

アプリ内のタイムラインのタブにある数（**まだ読んでいない投稿の数**）とは別のもので、数は一致しない。

| | ホーム画面のアイコン（これから作る） | タイムラインのタブ（今もある） |
| --- | --- | --- |
| 数えるもの | まだ見ていないお知らせ（投稿・コメント・予定の変更などの通知） | まだ読んでいない投稿 |
| 減る・消えるとき | アプリを開いたとき（0 になる） | 投稿を読んだとき（1 つずつ減る） |

例：新しい投稿が 1 件、予定の変更が 1 件届いたとき

- アイコン：**2** → アプリを開くと **0**
- タブ：**1** → その投稿を読むと **0**

他に検討した案（採らなかった）：

| 案 | 内容 | 採らなかった理由 |
| --- | --- | --- |
| 未読の投稿だけ | タブの数の全チームの合計 | 予定の変更やコメントが来てもアイコンの数が増えず、通知を見逃すと何も残らない |
| 両方を足す | 未読の投稿＋まだ見ていない予定・コメントの通知 | 同じ出来事を二重に数えない処理が要り、作りが複雑になる |

決めたこと：

- **数えるのは実際に送った通知だけ。** 種類ごとの設定でオフにしている通知や、自分の操作による通知は送らないので数えない
- **「見た」はアプリを開いたとき（前面に出たとき）。** どの画面を開いたかは問わない
- **利用者ごとに数える。** PC とスマホの両方で受け取っている人は、どちらかでアプリを開けば「見た」になる。
  ただしアイコンの数は、各端末で次に通知が届くかアプリを開いたときに更新される（他の端末のアイコンをすぐには消せない）
- テスト通知も 1 件として数える

## 3. 使う仕組み

Badging API（`navigator.setAppBadge(n)` / `navigator.clearAppBadge()`）。

- iOS・iPadOS **16.4 以降**と Android（Chrome）で使える
- iOS の条件：**ホーム画面に追加していること**、**通知を許可していること**
  （[WebKit の解説](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/)）。通知を使う人は満たす
- **Service Worker からも呼べる**ので、アプリを開いていなくても通知の受信時に更新できる
- 対応していない端末では、呼んでも何も起きない（`'setAppBadge' in navigator` で確かめてから呼ぶ）

## 4. サーバ側

### 4.1 送った通知を表に残す

今は #110 の「消えた通知から開く」ために、送った通知を**キャッシュ**に控えている（`PushSentLog`）。
これを**表**に移し、バッジの数にも使う。キャッシュはデプロイで消える（#110 の受け入れている弱点）ので、表に移すとその弱点も無くなる。

`push_notices`（新設）

| 列 | 内容 |
| --- | --- |
| id | |
| user_id | 送った相手 |
| nid | 通知ごとの目印（#110 と同じ） |
| tag | `post-123` など |
| url | 開く画面 |
| created_at | 送った時刻（索引：`user_id, created_at`） |

- 送ったときに 1 行足す（`PushNotificationJob`・テスト通知。今 `PushSentLog::record` を呼んでいるところ）
- 古い行は、足すときにその人の 30 日より前の分を消す（定期実行の仕組みを増やさない）

`users.push_seen_at`（追加。NULL 可）：その人が最後にアプリを開いた時刻

### 4.2 数え方

```
まだ見ていないお知らせの数 = その人の push_notices のうち created_at > push_seen_at の件数
（push_seen_at が NULL なら全件。ただし 30 日より前の分は消えているので数えない）
```

### 4.3 通知に載せる

`PushNotice` の `data` に `badge`（この通知を含めた数）を足す。受け取る人ごとに違うので、送る直前に数える。

```json
"data": { "url": "...", "nid": "...", "badge": 3 }
```

### 4.4 「見た」を記録する

| メソッド | パス | 送るもの | 返すもの |
| --- | --- | --- | --- |
| POST | `/api/push/seen` | — | `push_seen_at` を今にする。`{ badge: 0 }` |

### 4.5 #110 の「消えた通知から開く」を表に切り替える

`POST /api/push/recent` は `push_notices` から返す（中身と形は今と同じ）。`PushSentLog` は廃止する。

## 5. クライアント側

### 5.1 Service Worker（`public/sw.js`）

`push` で通知を表示するときに、`data.badge` があればアイコンの数を更新する。

```js
if (data.badge != null && 'setAppBadge' in self.navigator) { self.navigator.setAppBadge(data.badge); }
```

### 5.2 画面（`resources/assets/js`）

- **アプリの起動時と、前面に戻ったとき**（`visibilitychange`）に `POST /api/push/seen` を呼び、`navigator.clearAppBadge()` で消す
  - 裏の問い合わせなので、失敗しても利用者には知らせない（`silentErrors`）
- **ログアウト時**も消す（#110 で購読を消しているのと同じ場所）

## 6. 関連する修正：自分の投稿を未読にしない（タブの数。#123 に含める）

アイコンの数とは別に、タブの数（まだ読んでいない投稿）の既存の不具合も直す。

既読が付くのは投稿の詳細を開いたとき（`GET /api/posts/{id}`）で、投稿した直後はタイムラインに戻るだけなので
詳細を開かない（`Post.vue` の `afterPost`）。そのため**自分で投稿すると自分の未読が 1 つ増える**。

**投稿を作るときに、投稿した人の既読も作る**（`PostController::store`）。

```php
PostResponse::create([
    'user_id' => Auth::id(), 'post_id' => $post->id,
    'read_flg' => true, 'like_flg' => false, 'star_flg' => false,
    'created_id' => Auth::id(), 'updated_id' => Auth::id(),
]);
```

過去の投稿の分は、**一度だけ既読を作るマイグレーション**で直す。

- 対象：`posts.created_id` が自分で、その人の `post_responses` がまだ無い投稿
- 既にある `post_responses`（いいね・スターだけ付けた行など）は触らない
- 1 本の `INSERT ... SELECT` で入れる（旧サーバのデータ量でも一度で終わる）
- 巻き戻し（`down`）では、このマイグレーションで作った行だけを消せないので何もしない（コメントに明記する）

## 7. テスト

- PHPUnit
  - 送った通知が `push_notices` に残る／30 日より前の分が消える／利用者ごとに分かれる
  - `data.badge` が「見た後に送った数（この通知を含む）」になる
  - `POST /api/push/seen` で 0 に戻る／認証が要る
  - `POST /api/push/recent` が表から返す（#110 の既存テストがそのまま通る）
  - 投稿の登録で投稿した人の既読が作られ、その人のタブの数が増えない（§6）
  - マイグレーション：過去の自分の投稿に既読が入る／既にある `post_responses` を書き換えない
- Playwright（`tests/browser/specs/11-push.spec.js` に追加）
  - `navigator.clearAppBadge` を差し替えて、起動時・前面に戻ったときに呼ばれ、`/api/push/seen` が呼ばれることを確かめる
- 実機（iPhone）
  - 通知が届くたびにアイコンの数が増える（アプリを開いていない間）
  - アプリを開くと消える
  - 通知を許可していない場合に何も起きない（エラーにならない）
